## Project Goal

Build a series of three progressively complex Streamlit applications that teach
relational database concepts using DuckDB as the backend engine. The domain is a
**University Bookstore** — a familiar, relatable scenario for students.

The three-level arc:
| Level | Theme | SQL Concepts | App Mode |
|-------|-------|--------------|----------|
| 1 | Explore & Query | SELECT, WHERE, ORDER BY, LIMIT, BETWEEN | Read-only viewer |
| 2 | Relationships & Joins | JOIN, GROUP BY, HAVING, aggregate functions | Read-only analyst |
| 3 | Analytics & Power | Window functions, subqueries, indexes, INSERT | Read + Write |

## Database Schema

Five tables. One consistent dataset used across all three levels.

```
students  ──< purchases >── books
                 │
              courses
                 │
          course_books >── books
```

### students (13 rows)
student_id, name, email, major, year, gpa
- Majors: Computer Science (5), Electrical Engineering (3), Business Analytics (3),
  English Literature (1), Mechanical Engineering (1)
- Students 11–13 (Maria Santos, Kevin Osei, Priya Nair) have never made a purchase
- Years: freshman–senior mix

### courses (8 rows)
course_id, course_name, department, credits, semester, instructor
- 5 courses in Fall 2025, 3 in Spring 2026
- Departments: Computer Science, Electrical Engineering, Business Analytics, English Literature
- All taught by named instructors (Dr. Parsian teaches OMIS-105 equivalent)

### books (24 rows)
book_id, title, author, isbn, price, category, publisher
- Categories: Textbook, Reference, Novel
- Prices range from $9.99 (Elements of Style) to $224.99 (Electric Circuits)
- isbn carries a UNIQUE constraint (natural key lesson)
- Books 21–24 (AI: A Modern Approach, The Art of War, Python for Data Analysis,
  OS Concepts) have never been purchased — used for dead-stock LEFT JOIN demos

### course_books (20 rows)
course_id, book_id, required, edition
- Composite PK: (course_id, book_id)
- 10 required, 10 optional
- Resolves the M:M between courses and books

### purchases (60 rows)
purchase_id, student_id, book_id, course_id, purchase_date, quantity, total_amount
- Spans Aug 2025 – Apr 2026
- course_id is nullable (some purchases not tied to a course)
- total_amount stored explicitly (captures price at time of sale)

## Level 1 App — app_level1.py

### Architecture
- Single-file Streamlit app — 444 lines
- DuckDB connection opened `read_only=True` — no writes possible
- `@st.cache_resource` on the connection for performance

### Three pages
1. **Home** — dataset overview, row count metrics, 5-row table previews, 3 live story metrics
2. **Table Explorer** — pick any table, select columns, set row limit (0 = no LIMIT, max = table cardinality); SQL and explanation update live
3. **Query Builder** — 6 guided templates, each generating live SQL as controls change:
   - Books by category (WHERE + ORDER BY)
   - Students by major (WHERE + ORDER BY)
   - Top N most expensive books (ORDER BY + LIMIT)
   - Books in a price range (BETWEEN)
   - Students with GPA above a threshold (>=)
   - Purchases in a date range (BETWEEN on DATE)

### Pedagogical design
- SQL is always visible alongside results — students see the connection between UI action and SQL clause
- Plain-English explanation of each clause shown next to every query
- No free-text SQL input at Level 1 — all queries are controlled through widgets

## Level 3 App — app_level3.py

### Architecture
- Single-file Streamlit app — 931 lines
- DuckDB connection opened in **write mode** (no read_only) — INSERT and CREATE INDEX require writes
- `@st.cache_resource` on the connection; cache cleared after every write so reads refresh
- `run_write()` helper opens a fresh connection for each write, then clears the cache
- `matplotlib` used for all charts in the Analytics Dashboard

### Three pages
1. **Analytics Dashboard** — 6 analyses selectable from a dropdown; each shows a table, SQL, explanation, and a matplotlib chart:
   - Running total of revenue by date (SUM OVER ORDER BY) → dual-axis bar + line chart
   - Rank students by spend (ROW_NUMBER / RANK / DENSE_RANK toggle) → horizontal bar chart colored by major
   - Books ranked within category (RANK + PARTITION BY) → three-panel faceted bar chart
   - Each student vs their major's average (AVG OVER PARTITION BY) → bar chart with per-major avg line
   - Students above overall average spend (scalar subquery in HAVING) → bar chart with avg reference line
   - Books above their category average price (correlated subquery) → three-panel price chart with avg lines
2. **Add Records** — two tabs:
   - Insert a new student (form → generated SQL → run → table refreshes)
   - Insert a new purchase (dropdown pickers, auto-calculated total_amount)
3. **Index Lab**:
   - Status panel: CREATE / DROP buttons for 3 indexes on purchases
   - Timing comparison: runs query N times before and after index, reports speedup
   - EXPLAIN panel: side-by-side plans (without index left, with index right) rendered as
     code blocks via `st.code()` — shows SEQ_SCAN vs INDEX_SCAN in DuckDB's plan text

## Design Decisions & Rationale

**Why DuckDB?**
No server setup. Students run everything locally with `pip install duckdb`. Analytical
SQL (window functions, complex aggregations) runs fast even on a laptop.

**Why one dataset across all three levels?**
Students build intuition on familiar data. By Level 3, the bookstore feels like home,
which makes advanced concepts easier to absorb.

**Why store total_amount in purchases?**
Prices change over time. Storing the amount paid at the time of sale preserves
historical truth — a real-world RDBMS design lesson.

**Why is course_id nullable in purchases?**
A student might buy a book out of interest, not for a specific course. Nullable FKs
are a legitimate design choice worth discussing explicitly.

**Why a composite PK on course_books?**
Teaches that PKs don't have to be a single auto-increment integer — and introduces
the concept of natural composite keys.

## Ultimate App — app_bookstore.py

### Architecture
- Single-file Streamlit app — 1320 lines
- DuckDB connection in **write mode** — supports INSERT for purchases and students
- `run_write()` helper with cache clear on every write
- `matplotlib` for all charts; custom dark CSS for polished UI
- SQL visible on demand via `st.expander` on every insight

### Six sections
1. **🏠 Executive Dashboard** — 6 KPI metrics, business alerts (inactive students + dead
   stock via LEFT JOIN anti-join), monthly revenue bar, dept revenue, smart narrative insights
2. **👥 Student Intelligence** — ranked leaderboard with window functions, never-purchased
   alert table, spend by major, spend by academic year (two-panel chart)
3. **📖 Catalog & Inventory** — full LEFT JOIN catalog with purchase stats and status,
   dead-stock alert, top-10 revenue bar, sold vs never-sold grouped bar by category,
   price vs revenue bubble scatter
4. **💰 Revenue Analytics** — cumulative revenue area+bar chart (window function),
   Fall vs Spring comparison, required vs optional dual pie, per-student vs major avg bar
5. **✏️ Manager Actions** — record purchases (auto total_amount), register students,
   recent activity feed; all writes show the INSERT SQL before execution
6. **🔬 SQL Playground** — free-text SQL editor (SELECT only, safety-guarded), 10 example
   queries preloaded, auto-detected charting: Bar, Horizontal Bar, Pie, Line, Area, Scatter;
   column pickers for x/y axes, 4 colour palettes; schema quick-reference panel

### Key SQL patterns demonstrated
- LEFT JOIN anti-join (`WHERE p.purchase_id IS NULL`) for inactive customers + dead stock
- `ROW_NUMBER() OVER` for customer ranking
- `SUM() OVER (ORDER BY date)` for cumulative revenue
- `AVG() OVER (PARTITION BY major)` for group comparisons
- Multi-table aggregation across 4 joined tables
- `COALESCE` for handling NULL aggregates on unsold books
- Free-form student SQL with live chart rendering

## How to Run All Three Levels + Ultimate App

```bash
# 1. Install dependencies
pip install duckdb streamlit pandas matplotlib

# 2. Seed the database (only needed once, or to reset)
python seed.py

# 3. Run Level 1 — read-only explorer
streamlit run app_level1.py

# 4. Run Level 2 — joins & aggregation
streamlit run app_level2.py

# 5. Run Level 3 — window functions, INSERT, indexes, charts
streamlit run app_level3.py

# 6. Run the ultimate bookstore intelligence platform
streamlit run app_bookstore.py
```
