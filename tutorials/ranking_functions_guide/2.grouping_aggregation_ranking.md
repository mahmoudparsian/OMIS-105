---

## 📑 Step 1: Schema and Sample Data

## 📑 Step 2: Grouping Data with Aggregations

### Example 1: Total sales amount per region

```sql
SELECT 
       region, 
       SUM(amount) AS total_sales
FROM 
       sales
GROUP BY 
       region
ORDER BY 
       region;
```

✅ Output

<!-- RESULT -->

| region | total_sales |
|--------|------------:|
| East   |     2550.00 |
| North  |     3500.00 |
| South  |     1550.00 |

*(3 rows)*

<!-- /RESULT -->

---
### Example 1.1: Total sales amount per region where total sales over 2000 (filtering the result set (after aggregation))

```sql
SELECT 
       region, 
       SUM(amount) AS total_sales
FROM 
       sales
GROUP BY 
       region
HAVING 
       total_sales > 2000
ORDER BY 
       region;
```

✅ Output

<!-- RESULT -->

| `region` | `total_sales` |
|--------|------------:|
| East   |     2550.00 |
| North  |     3500.00 |

*(2 rows)*

<!-- /RESULT -->

> 💡 DuckDB lets `HAVING` use the alias `total_sales`. Many other
> databases do not; there you write `HAVING SUM(amount) > 2000`, which
> also works in DuckDB.

---

### Example 2: Average sales amount per product

```sql
SELECT 
        product, 
        AVG(amount) AS avg_sales
FROM 
        sales
GROUP BY 
        product
ORDER BY 
        product;
```

✅ Output

| Phone   |  866.6666666666666 |

| Laptop  |   1233.33 |
| Phone   |    866.67 |
| Tablet  |     650.0 |

### Example 3: Minimum and Maximum sales amount per region

```sql
SELECT 
       region, 
       MIN(amount) AS min_sale, 
       MAX(amount) AS max_sale
FROM 
       sales
GROUP BY 
       region
ORDER BY 
       region;
```

✅ Output

<!-- RESULT -->

| `region` | `min_sale` | `max_sale` |
|--------|---------:|---------:|
| East   |   700.00 |  1000.00 |
| North  |   800.00 |  1500.00 |
| South  |   600.00 |   950.00 |

*(3 rows)*

<!-- /RESULT -->

-----

===> ERROR: we can not use the `amount` column in the `SELECT`:
it is not in the `GROUP BY`, and it is not inside an aggregate function.

```sql
SELECT 
       region, 
       amount,
       MIN(amount) AS min_sale, 
       MAX(amount) AS max_sale
FROM 
       sales
GROUP BY 
       region;
```

<!-- ERROR -->

```text
Binder Error: column "amount" must appear in the GROUP BY clause or must be part of an aggregate function.
Either add it to the GROUP BY list, or use ANY_VALUE("amount") if the exact value of "amount" is not important.

LINE 3:        amount,
               ^^^^^^
```

<!-- /ERROR -->

To see **all** the amounts of each region, put them in one value
with an aggregate function: `string_agg()` builds one text value,
`list()` builds a DuckDB list.

```sql
SELECT 
       region, 
       string_agg(amount, ',' ORDER BY sale_id) AS list_of_amounts,
       list(amount ORDER BY sale_id) AS amounts_as_list,
       MIN(amount) AS min_sale, 
       MAX(amount) AS max_sale
FROM 
       sales
GROUP BY 
       region
ORDER BY 
       region;
```

<!-- RESULT -->

| `region` | `list_of_amounts`        | `amounts_as_list`            | `min_sale` | `max_sale` |
|--------|------------------------|----------------------------|---------:|---------:|
| East   | 700.00,1000.00,850.00  | [700.00, 1000.00, 850.00]  |   700.00 |  1000.00 |
| North  | 1200.00,1500.00,800.00 | [1200.00, 1500.00, 800.00] |   800.00 |  1500.00 |
| South  | 950.00,600.00          | [950.00, 600.00]           |   600.00 |   950.00 |

*(3 rows)*

<!-- /RESULT -->

## 📑 Step 3: Ranking Data with RANK()

### Example 1: Rank regions by total sales

```sql
WITH Region_Sales AS (
  SELECT region, 
         SUM(amount) AS total_sales
  FROM 
         sales
  GROUP BY 
         region
)
SELECT 
       region, 
       total_sales,
       RANK() OVER (ORDER BY total_sales DESC) AS sales_rank
FROM 
       Region_Sales
ORDER BY 
       sales_rank;
```

✅ Output

<!-- RESULT -->

| `region` | `total_sales` | `sales_rank` |
|--------|------------:|-----------:|
| North  |     3500.00 |          1 |
| East   |     2550.00 |          2 |
| South  |     1550.00 |          3 |

*(3 rows)*

<!-- /RESULT -->

----

### Example 1.1: Find Top region based on total-sales. 

```sql
WITH 
Region_Sales AS (
  SELECT region, 
         SUM(amount) AS total_sales
  FROM 
         sales
  GROUP BY 
         region
)
,
RANKED_REGION AS (
  SELECT 
       region, 
       total_sales,
       RANK() OVER (ORDER BY total_sales DESC) AS sales_rank
  FROM 
       Region_Sales
)
SELECT region, 
       total_sales,
       sales_rank
FROM 
       RANKED_REGION
WHERE
       sales_rank <= 1; 
```

✅ Output

<!-- RESULT -->

| `region` | `total_sales` | `sales_rank` |
|--------|------------:|-----------:|
| North  |     3500.00 |          1 |

*(1 row)*

<!-- /RESULT -->

----

### Example 2: Rank products by average sales

```sql
WITH Product_Avg AS (

SELECT

FROM 
       Product_Avg
ORDER BY 
       avg_rank;
```

✅ Output

<!-- RESULT -->

| `product` | `avg_sales` | `avg_rank` |
|---------|----------:|---------:|
| Laptop  |   1233.33 |        1 |
| Phone   |    866.67 |        2 |
| Tablet  |     650.0 |        3 |

*(3 rows)*

<!-- /RESULT -->

## 📑 Step 4: Using DENSE_RANK()

👉 `DENSE_RANK()` works like `RANK()`, but **without gaps** when there are ties.

### Example: Rank regions by total sales (dense)

```sql
WITH Region_Sales AS (
  SELECT 
         region, 
         SUM(amount) AS total_sales
  FROM 
         sales
  GROUP BY 
         region
)
SELECT 
       region, 
       total_sales,
       DENSE_RANK() OVER (ORDER BY total_sales DESC) AS dense_rank
FROM 
       Region_Sales
ORDER BY 
       dense_rank;
```

✅ Output

<!-- RESULT -->

| `region` | `total_sales` | `dense_rank` |
|--------|------------:|-----------:|
| North  |     3500.00 |          1 |
| East   |     2550.00 |          2 |
| South  |     1550.00 |          3 |

*(3 rows)*

<!-- /RESULT -->

*(Here results are the same, but in cases of ties, `RANK()` would skip numbers while `DENSE_RANK()` would not.)*

---

## 📑 Step 5: Using ROW_NUMBER()

👉 `ROW_NUMBER()` gives each row a unique sequential number, even if values tie.

### Example: Numbering products by average sales

```sql
WITH Product_Avg AS (
  SELECT 
         product, 
         ROUND(AVG(amount), 2) AS avg_sales
  FROM 
         sales
  GROUP BY 
         product
)
SELECT 
       product, 
       avg_sales,
       ROW_NUMBER() OVER (ORDER BY avg_sales DESC) AS rownum
FROM 
       Product_Avg
ORDER BY 
       rownum;
```

✅ Output

<!-- RESULT -->

| `product` | `avg_sales` | `rownum` |
|---------|----------:|-------:|
| Laptop  |   1233.33 |      1 |
| Phone   |    866.67 |      2 |
| Tablet  |     650.0 |      3 |

*(3 rows)*

<!-- /RESULT -->

---

## 📑 Key Takeaways

- **Grouping + Aggregation** lets you summarize data by categories.  

- Aggregates include: `SUM`, `AVG`, `MIN`, `MAX`, `COUNT`.  

- **RANK()** → ranking with possible gaps in numbering.  

- **DENSE_RANK()** → ranking with no gaps.  

- **ROW_NUMBER()** → unique sequential number per row.  

- Combine `WITH` (CTEs) + ranking to make queries clearer.

- Add `ORDER BY` when the order of the output matters.

---

## 📑 Step 2: First-Level Grouping (per region + product)

👉 Compute total sales per **region + product**.

```sql
WITH Region_Product_Sales AS (
  SELECT 
          region, 
          product, 
          SUM(amount) AS total_sales
  FROM 
          sales
  GROUP BY 
          region, product
)
SELECT * 
FROM Region_Product_Sales
ORDER BY region, product;
```

✅ Output

<!-- RESULT -->

| `region` | `product` | `total_sales` |
|--------|---------|------------:|
| East   | Laptop  |     1000.00 |
| East   | Phone   |      850.00 |
| East   | Tablet  |      700.00 |
| North  | Laptop  |     2700.00 |
| North  | Phone   |      800.00 |
| South  | Phone   |      950.00 |
| South  | Tablet  |      600.00 |

*(7 rows)*

<!-- /RESULT -->

## Compute total sales per **region + product** if and only if the total sales is greater than 1000.

solution-1:

```sql
WITH Region_Product_Sales AS (
  SELECT 
          region, 
          product, 
          SUM(amount) AS total_sales
  FROM 
          sales
  GROUP BY 
          region, product
)
SELECT * 
FROM Region_Product_Sales
WHERE total_sales > 1000;
```

<!-- RESULT -->

| `region` | `product` | `total_sales` |
|--------|---------|------------:|
| North  | Laptop  |     2700.00 |

*(1 row)*

<!-- /RESULT -->

OR

solution-2:

```sql
  SELECT 
          region, 
          product, 
          SUM(amount) AS total_sales
  FROM 
          sales
  GROUP BY 
          region, product
  HAVING
          total_sales > 1000;
```

<!-- RESULT -->

| `region` | `product` | `total_sales` |
|--------|---------|------------:|
| North  | Laptop  |     2700.00 |

*(1 row)*

<!-- /RESULT -->

## 📑 Step 3: Second-Level Grouping (per region)

👉 Now group again on **region**, aggregating across products.

```sql
WITH Region_Product_Sales AS (
  SELECT 
         region, 
         product, 
         SUM(amount) AS total_sales
  FROM 
         sales
  GROUP BY 
         region, product
),
Region_Totals AS (
  SELECT 
         region, 
         SUM(total_sales) AS region_total
  FROM 
         Region_Product_Sales
  GROUP BY 
         region
)
SELECT * 
FROM Region_Totals
ORDER BY region;
```

✅ Output

<!-- RESULT -->

| `region` | `region_total` |
|--------|-------------:|
| East   |      2550.00 |
| North  |      3500.00 |
| South  |      1550.00 |

*(3 rows)*

<!-- /RESULT -->

---

## 📑 Key Takeaways

- First CTE (`Region_Product_Sales`) → groups by **region + product**.  

- Second CTE (`Region_Totals`) → groups by **region** using the first result.  

- This is how you achieve **multi-level grouping** with subqueries.
