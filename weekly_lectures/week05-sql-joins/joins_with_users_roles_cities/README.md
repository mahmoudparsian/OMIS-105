# Users / Roles / Cities — Join Practice Database

A tiny, three-table DuckDB database for practicing `JOIN`,
`LEFT JOIN ... IS NULL`, `COALESCE`, and `GROUP BY` without the
noise of a big dataset. Everything lives in this one folder — no
external downloads, no server to install.

This folder started as a copy of
`resources/sample_databases/users_roles_cities_small/`. The data
here is larger, and it now includes users with **no role** and
**no city**, which the Week 5 join topics need.

## The Story

Imagine a small internal tool that a company uses to track its
people. Every person who logs in is a **user**. A user *should* have
a **role** (what they're allowed to do) and a **city** (for reporting
and support routing) — but some records are not finished yet.

The team defined all the roles and cities they *might* need, up
front — seven roles, eight cities. Today, 36 users have signed up.
Not everything is filled in:

- **`tester`** and **`QA`** are defined roles, but nobody has them —
  those jobs haven't been staffed.
- **`Cupertino`** and **`Detroit`** are defined cities, but nobody
  lives there yet — the company hasn't hired in those offices.
- **5 users have no role** yet (`role_id` is `NULL`): Diego, Hana,
  Victor, Zoe, Tom.
- **4 users have no city** yet (`city_id` is `NULL`): Grace, Ravi,
  Zoe, Tom.
- **Zoe** and **Tom** have neither.

This "not everything is used yet" data is common in real systems.
It is what makes `INNER JOIN` and `LEFT JOIN` give different answers,
and what makes `LEFT JOIN ... IS NULL` genuinely useful.

## Tables

| Table | Rows | Columns | What it holds |
|-------|-----:|---------|----------------|
| `roles`  | 7  | `id`, `role`, `description` | admin, user, superuser, tester, QA, developer, analyst — plus a one-line description of what each role does |
| `cities` | 8  | `id`, `city`, `population` | New York, Philadelphia, San Francisco, Sunnyvale, Cupertino, Detroit, San Jose, Santa Clara — plus each city's population (2020 U.S. Census) |
| `users`  | 36 | `id`, `name`, `role_id` (FK → `roles.id`), `city_id` (FK → `cities.id`) | one row per person; every name is unique |

```
roles (id, role, description)     cities (id, city, population)
       ▲                                  ▲
       │ role_id (may be NULL)            │ city_id (may be NULL)
       └──────────────── users ───────────┘
                  (id, name, role_id, city_id)
```

`role_id` and `city_id` may be `NULL` ("not assigned yet"). Any
non-`NULL` value must exist in the other table — the `FOREIGN KEY`
rejects anything else.

`description` and `population` are there so that a join returns
more than just a name. For example, joining `users` to `cities`
lets you filter users by city size (`WHERE c.population > 1000000`).

## Data Gaps (by design)

| Question | Answer | Found by |
|----------|--------|----------|
| Which roles are never used? | `tester`, `QA` | `roles LEFT JOIN users ... WHERE u.id IS NULL` (notebook **I5**) |
| Which cities have no users? | `Cupertino`, `Detroit` | `cities LEFT JOIN users ... WHERE u.id IS NULL` (notebook **I6**) |
| Which users have no role? | Diego, Hana, Victor, Zoe, Tom | `WHERE role_id IS NULL` (notebook **S10**) |
| Which users have no city? | Grace, Ravi, Zoe, Tom | `WHERE city_id IS NULL` |
| Which users have neither? | Zoe, Tom | `LEFT JOIN` both tables (notebook **I9**) |

## Usage

**Notebook** — no setup step needed. The notebook builds a fresh
in-memory database from `01_schema.sql` and `02_records.sql` every
time it starts:

```bash
cd joins_with_users_roles_cities
marimo edit notebook.py
```

**DuckDB CLI or qStudio** — build a database file first:

```bash
cd joins_with_users_roles_cities
./create_duckdb.sh                  # creates users_roles_cities.duckdb
duckdb users_roles_cities.duckdb    # then paste any query
```

- `create_duckdb.sh` requires the
  [DuckDB CLI](https://duckdb.org/docs/installation/) on your `PATH`.
  Run it again any time — it deletes and rebuilds the file.
- `notebook.py` requires `marimo`, `duckdb`, `pandas`, and
  `matplotlib` (see the
  [software installation guide](../../../software_installation/README.md)).
